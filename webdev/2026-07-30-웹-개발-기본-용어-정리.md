### Context
웹 서비스를 개발하고 이해하기 위해서는 기본적인 용어들의 개념을 명확히 알아두는 것이 중요합니다. 고객이 직접 보는 화면부터 뒤에서 데이터를 처리하고 저장하는 방식, 그리고 이 모든 요소가 어떻게 소통하는지에 대한 이해는 안정적이고 효율적인 서비스 구축의 기초가 됩니다. 오늘 학습한 내용은 이러한 웹 개발의 핵심 구성 요소와 개념들을 정리한 것입니다.

### Core
*   **프론트엔드 (Frontend)**
    *   **정의:** 사용자가 웹 브라우저나 모바일 앱을 통해 직접 보고 상호작용하는 서비스의 '시각적인' 영역입니다. HTML, CSS, JavaScript 등으로 구현되며, 사용자 경험(UX)을 담당합니다.

*   **백엔드 (Backend)**
    *   **정의:** 사용자에게는 보이지 않는 곳에서 서비스의 핵심 로직을 처리하고 데이터를 관리하는 시스템입니다. 사용자 요청 처리, 데이터베이스 연동, 보안 및 비즈니스 로직 구현 등을 담당합니다.

*   **데이터베이스 (Database)**
    *   **정의:** 서비스 운영에 필요한 모든 데이터를 체계적으로 저장하고 관리하는 시스템입니다. 고객 정보, 주문 내역, 콘텐츠 등 다양한 정보를 안정적이고 효율적으로 저장하고 검색할 수 있도록 돕습니다.

*   **서버 (Server)**
    *   **정의:** 클라이언트(웹 브라우저, 앱 등)의 요청을 수신하고 처리하여 적절한 응답을 다시 보내주는 역할을 하는 컴퓨터 시스템(하드웨어) 또는 소프트웨어(프로그램)입니다. 웹 서비스를 사용자에게 제공하는 핵심 인프라입니다.

*   **API (Application Programming Interface)**
    *   **정의:** 서로 다른 소프트웨어 시스템이 데이터를 주고받으며 소통할 수 있도록 정의된 '인터페이스'이자 '규칙'의 집합입니다. 주로 프론트엔드와 백엔드 간, 또는 여러 서비스 간의 데이터 교환 통로로 사용됩니다.

*   **환경변수 (.env)**
    *   **정의:** 애플리케이션이 실행되는 환경에 따라 달라지거나, 데이터베이스 접속 정보, API 키 등 외부에 노출되어서는 안 되는 민감한 설정을 분리하여 관리하는 변수입니다. `.env` 파일은 이러한 환경변수를 저장하는 일반적인 방법 중 하나입니다.

*   **RLS (Row-Level Security)**
    *   **정의:** 데이터베이스 테이블 내에서 특정 조건(예: 사용자 ID)에 따라 개별 데이터 행(row)에 대한 접근 권한을 제어하는 보안 기능입니다. 이를 통해 사용자는 자신에게 허용된 데이터만 조회하거나 수정할 수 있습니다.

*   **해시 (Hash)**
    *   **정의:** 원본 데이터를 고정된 길이의 고유한 값(해시 값)으로 변환하는 단방향 암호화 기술입니다. 주로 데이터의 위변조 여부 확인(무결성 검증)이나 비밀번호와 같은 민감 정보를 안전하게 저장할 때 사용됩니다. 원본을 복원할 수 없습니다.

*   **웹훅 (Webhook)**
    *   **정의:** 특정 이벤트(예: 결제 완료, 새 댓글 작성)가 발생했을 때, 해당 정보를 실시간으로 미리 지정된 URL로 HTTP POST 요청을 통해 자동으로 전송하는 메커니즘입니다. '이벤트 기반 알림' 방식으로 시스템 간 연동에 활용됩니다.

*   **배포 (Deployment)**
    *   **정의:** 개발 환경에서 완성된 서비스나 애플리케이션을 실제 사용자들이 접근하고 사용할 수 있도록 운영 환경(서버)에 설치하고 실행하는 전 과정을 의미합니다.

### Insight
이러한 기본 용어들을 명확히 이해하는 것은 웹 서비스가 어떻게 구성되고 작동하는지에 대한 큰 그림을 그리는 데 필수적입니다. 프론트엔드와 백엔드가 API를 통해 소통하고, 백엔드는 데이터베이스에서 정보를 가져오며, 서버는 이 모든 요청을 처리합니다. 환경변수는 민감한 정보를 보호하고, RLS와 해시는 데이터 보안을 강화하며, 웹훅은 실시간 이벤트 처리를 돕습니다. 최종적으로 배포를 통해 서비스가 세상에 공개됩니다. 각 요소의 역할과 상호작용을 파악함으로써, 문제 발생 시 원인을 더 쉽게 파악하고 효율적인 개발 전략을 세울 수 있을 것입니다.
